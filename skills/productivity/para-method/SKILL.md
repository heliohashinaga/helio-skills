# PARA Method

Use when deciding where a note belongs, or when organizing or cleaning up the
Obsidian vault.

## Quick start

Rank by actionability, highest first: **Projects** (finishable outcome) > **Areas** (ongoing standard) > **Resources** (reference) > **Archives** (done or dormant). The vault's `1-`–`4-` folders map to Projects, Areas, Resources and Archives in that order. There is no inbox folder — triage happens in the answer, not in a folder.

## Workflow

When given a note, file, or idea, answer in order — first "yes" wins:

1. Concrete deliverable or desired result? → `1-Projects/`
2. Ongoing responsibility to maintain? → `2-Areas/`
3. Only useful as support, background, or lookup? → `3-Resources/`
4. Otherwise (finished, obsolete, low-value)? → `4-Archives/`
5. Still uncertain after 1–4? → leave the note where it is and state in one line what is missing.

Respond with the folder, a one-line reason, ambiguities or follow-ups, and move suggestions for related notes. Example:

> `3-Resources/` — book summary, no deadline or owner, pure reference. No ambiguities. Related: link it from the other notes by the same author.

## Reference

- Classify quickly and archive aggressively; a note left unclassified is worse than one filed imperfectly.
- Favor links over copying content; avoid duplicate placement unless a note clearly serves two purposes.
- Review Projects often so completed work does not linger; review Areas periodically so standards stay relevant.
